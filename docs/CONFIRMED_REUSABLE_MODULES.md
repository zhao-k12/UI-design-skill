# 已确认的页面模块与复用边界

## 独立模块组装能力

`module_panel`、`summary_panel`、`steps_panel` 接收显式完整节点，模块自身持有左右 24px、后方 16px 外边距和内部 16px 留白，不再套外层 gap。摘要标题和可选 Tag 横排；静态 Remix close-line 为 16px，距顶部及右侧 16px；摘要元信息仅由 summary-meta 持有一次顶部 16px。步骤必须传入官方 Steps，作为独立平级模块，不附加业务状态或交互。

`form_section(..., columns='auto')` 可选共享 form-grid-fluid，按最小 340px 字段宽度自适应换行；不足一列时以容器宽度为准。统一 24px 网格行距并归零 FormItem 底部 margin，避免重复行距。调用者仍须依据实际标签、占位文案、图标与 labelWidth 检查可读宽度；任意更长文案不保证自动适配。原有三列、四列行为保持不变。

本规范归纳用户确认的设计，不包含风电场页面的业务数据。下列数值是用户确认的设计目标；实际支持范围以下方已接入能力为准，不能仅凭阅读此文档宣称生成结果已达到。

## 已接入的样式角色

完整 Tree 的容器或组件可显式填写 `designRole`，目前允许 `page-shell`、`sidebar`、`brand`、`topbar`、`topbar-tool`、`topbar-tool-large`、`topbar-user`、`breadcrumb`、`search-panel`、`search-grid`、`search-field`、`search-label`、`search-actions`、`table-panel`、`table-toolbar`、`table-actions`、`row-actions`、`row-action`、`tab-label`、`tab-count`、`pagination`。角色只选择共享样式；样式在 `adapters/html/confirmed-modules.css`，导出器打包进离线页面。未知角色会被拒绝，不填写角色时旧页面保持原行为。

表单及详情还可按需选择 `form-section`、`form-section-title`、`form-grid`、`form-grid-three`、`detail-add`、`detail-action`、`summary-header`、`summary-title`、`summary-meta`、`progress-steps`、`page-actions`。以下为显式选择的设计覆盖，不自动套用到其他内容：`upload-icon-large`（图标 52px、#2d8cf0）、`upload-copy`（两行间距 6px）、`success-icon`（16px 绿色状态图标）、`muted-cell`（#c5c8ce）、`uploaded-value`（状态图标、数值和删除图标的组合）。这些值来自已确认页面；只在新任务适用或用户明确要求时使用，不据此虚构内容或状态。

`scripts/confirmed_modules.py` 提供 `sidebar`、`topbar`、`breadcrumb`、`search_panel`、`table_panel`、`action_column`、`light_tag`、`project_logo`、`page_shell`，接受调用者明确给出的菜单、字段、行数据、操作与状态，直接返回标准完整 Tree，既不读取历史页面也不保存引用。侧栏始终使用默认 Logo，除非用户明确要求其他 Logo 或文字替代；仅用户明确要求项目素材时用 `brand_node=project_logo('project-brand', path)` 替换，支持 PNG、JPEG、WebP 和通过安全校验的 SVG，默认按比例高 32px 并嵌入离线页面。SVG 中脚本、外部资源和不安全标记会被拒绝。顶部栏默认复用五个工具、已确认风景头像和“钱多多”；明确传入姓名或头像时覆盖，`username=None` 移除用户区。折叠的父菜单在没有可见子项数据时用 `expandable=True`，不推测其子项；其他一级项按实际结构配置。`table_panel` 默认演示分页总数100、每页10条、第一页；明确配置优先，`page=None` 可移除。Tabs 可配置数量徽标；字段、按钮和菜单项可传 `sourceIds`，其余来源仍须由调用者逐项绑定。

在读取入口与当前原型后，使用这些函数一次组装标准 Tree，再交给现有 `html_fast_workflow.py render` 和 `finalize`；不要把配置作为新的替代 Tree 输入。典型调用（演示变量均为本次任务实际识别的数据）：

```python
from confirmed_modules import sidebar, topbar, breadcrumb, search_panel, table_panel, action_column, page_shell
side = sidebar('side', menu_entries, active_name=active_name, open_names=open_names)
header = topbar('header', username=current_username)
trail = breadcrumb('trail', breadcrumb_labels)
query = search_panel('query', search_fields)
results = table_panel('results', table_columns, table_rows, tabs=status_tabs, buttons=toolbar_buttons, page=page_props)
root = page_shell('page', sidebar_node=side, topbar_node=header, breadcrumb_node=trail, sections=[query, results])
# 将 root 放入当前任务的完整 content，按原型补齐各节点 sourceIds，连同独立观察/复扫写入 job.json。
```

`action_column('actions')` 返回标准表格列；各行显式提供 `actions` 数组，每项包含 `label`、`icon` 和 `tone`（普通为 `''`，危险为 `'danger'`），内容 Tree 顶层 `icons` 显式列出所有可能的 Remix 名称。分页器的左右和下拉箭头由已打包的 Remix 图形呈现。`table_panel` 对没有固定宽度、最小宽度或复杂表头的列按本次内容测量最小宽度；存在末尾行操作时保留其所需宽度，其余列平分剩余空间。静态页面通过 CSS 随视口变化重排列宽，窄屏时水平滚动；数据修改后须重新生成以重新测量内容。遇到显式宽度或复杂表头默认保留原配置，也可显式设置 `equal_gaps=False`。强制均分与这些配置冲突时会报错。

已用真实导出器和浏览器测试三种不同业务标签、2/3/4 个查询字段及有无 Tabs 的组合，检查默认及项目 Logo 32px、侧栏 256px、顶部栏 64px、输入框 34px、面包屑与模块间距、四字段时操作换行、徽标、分页图标、斑马纹、行高和不同记录的操作数量。表格等间距检查测量生成时的列宽减去预检得到的各列内容最小宽度；这是机器布局检查，不代替视觉验收。测试不证明所有设计目标或响应式场景已实现。当前仍未完整支持含特殊资源的 SVG、已交付静态页面中数据变化后的自动重排、所有表格细节及复杂页面；遇到缺口不能复制过去页面的业务内容。

## 决策与来源

本次用户指令和原型明确的业务内容、状态及特殊布局优先；本规范作为默认设计。菜单名称、字段、数据、选项、业务状态、行操作从本次原型读取，不从本规范或历史页面复制。模块可以独立使用或组合；页面不需要的查询区、表格、Tabs、选择列等不要凭模板自动增加。用户要求完整 Tree，保存的 Tree 须包含全部节点、实例、行数据和来源绑定，不能仅保存模块引用或简写 Tree。

## 页面框架与侧栏

普通后台页面默认同时使用侧栏和顶部导航，即使原型未绘制顶栏；弹窗默认不附加全局侧栏和顶栏。本次用户明确要求优先。菜单业务内容仍以当前原型为依据，不能从其他页面带入。

默认背景 `#f8f8f9`；有侧栏时宽 256px，白色背景至少铺满视口或内容高度，右侧柔和外阴影；Logo 与菜单属于同一侧栏，Logo 区高 64px，Logo 左侧 24px、整体高 32px 并按比例缩放。除非用户明确要求其他 Logo 或文字替代，否则始终使用 `assets/default-logo.svg`，不要重复添加其中已有的文字。一级与二级菜单行高 52px；一级左图标 16px、`#808695`，箭头 `#b5b5b5`；无子菜单的一级菜单选中时图标与文字同为蓝色。菜单项、图标、层级、展开与选中状态均由本次原型配置，不固定数量或展开项。

可展开与不可展开的一级菜单，左侧图标与菜单名称间距均为 8px；图标及文字在行内垂直居中。

## 顶部导航与面包屑

顶部导航高 64px，有侧栏时从侧栏右边界开始，无侧栏时可占满页面宽度，下边缘使用柔和阴影。默认工具从左至右：收起、刷新；右侧大屏、全屏、消息、头像与名称；可根据项目要求配置。图标分别为 Remix `indent-decrease`（18px）、`reset-right-line`、`slideshow-line`、`fullscreen-line`、`notification-3-line`（后四项 16px），颜色 `#808695`；工具容器高 64px、左右 padding 12px，顶部栏两端无额外 padding。默认复用已确认的风景头像和“钱多多”，头像 24px、图文间距 12px，组合容器高 64px、左右 padding 12px；用户指定项目身份时覆盖默认内容。

面包屑按当前菜单的真实层级配置文字：一级页面只显示当前名称，有父级才显示实际父级；不自动添加“工作台”等父级。距侧栏右边及顶部栏下边各 12px；行高及容器高 20px，字重 400，父级 `#999999`，当前级 `#515a6e`，分隔符 `#dcdee2`。无侧栏或顶部栏时根据实际边界重新安排，不保留空白占位。

## 查询模块

默认左右距主区边界 24px；有面包屑与顶部栏时顶部距导航底部 44px。白色容器圆角 4px、padding 16px；默认四列等宽，标签水平排列并按最长七字宽度对齐。输入框和选择框高 34px、圆角 4px、边框 `#dcdee2`、提示文字 `#ccc`。查询与重置靠右，图标分别为 `search-line`、`refresh-line`，16px，与文字间距 6px；查询图标白色、重置图标 `#808695`。三字段可与操作同排、四列满时操作换行；小屏或内容不足时自然换行。字段类型、文案、是否有折叠与额外按钮由原型决定。

同列的输入、选择和日期控件应占相同可用宽度。选择箭头和日期图标使用 Remix 图形、颜色 `#808695`，替换原组件图形时不得重叠。按钮图标与文字统一垂直居中；新增按钮默认配置 `add-large-line`，图标 14px。

## 表格模块

默认与查询区相隔 16px，左右距主区边界各 24px；无查询区时按实际页面布局放置。Tabs 可选，显示数量时使用独立徽标：背景 `#f8f8f9`、1px 边框 `#dcdee2`、文字 `#515a6e`；Tab 高 37px，内容上下 padding 8px、左右 16px，文字与徽标间距 6px，Tab 之间 16px，底部有灰色通栏及选中蓝线。工具按钮间距 12px、顶部距模块 16px；灰线距表头 16px。当 Tab 与 32px 按钮顶部对齐时，按钮底部到表头为 21px，不能同时声称为 16px。

无 Tabs 且左侧无其他内容时工具按钮靠左，距模块左侧 16px；不保留 Tabs 的底线。分页器右侧距模块边界 16px。表格内容应垂直居中，底线与表格内容边界一致。

表头高 40px，数据行高 48px，内容白色与 `#f8f8f9` 交替。首列内容离表格左边 18px；整列各行最多只有一个操作时，操作内容距右边 32px，否则沿用 18px，操作表头对齐操作组中心。列按内容所需宽度动态分配，剩余空间在相邻列之间均匀分配，内容过宽允许横向滚动。行操作可按需配置 Remix 图标与名称（示例查看 `eye-line`、编辑 `edit-box-line`、删除 `delete-bin-line`），图标 16px，相邻操作组间距 16px，避免内层多余 margin。默认分页第 1 页、10 条/页、10 页、Remix 箭头并垂直居中；100 条仅作为总数未知时的演示默认，原型或用户明确给出的分页优先。

普通标签默认使用 View UI Plus Tag 的浅色系列；静态标签可调用 `light_tag(id, label, color='blue')`，重复数据通过官方 `Tag` 的 `color` 绑定 `blue`、`green`、`cyan` 等官方浅色系列。用户或原型明确指定其他样式时按指定配置，不强制改写。

## 复核与性能

按当前任务将模块一次配置并组合；一次预览后集中检查内容来源、菜单和业务状态、实际尺寸、背景、图标、阴影、列间距、分页与边界，问题合批修正并重看。每个页面重新校对其原型，不复用其他页面的业务内容或视觉 PASS。记录真实的准备、编写、生成、复核和发布用时；未测得的部分不猜测，五分钟是目标而非保证。不同字段数量、有无 Tabs、不同菜单与不同行操作的配置须实际测试，检查长内容、窄屏和空值，不能只验证文字或模板结构。

演示记录的编号格式、名称、字段长度、业务取值和地区日期应与当前原型相近；不将补充数据称为来源事实，保留必要空值及内部来源区分。交付静态页默认检查输入框不可编辑、菜单和按钮鼠标经过无变化，并检查窄屏滚动条和滚轮仍可用；用户明确要求的局部经过效果单独启用并验收。
# 列表页的滚动与对齐补充

- 默认侧栏、顶部导航、面包屑依次处于更高层级并保持可见，内容纵向滚动；面包屑下内边距 12px，紧随其后的查询模块上外边距 0。无这些区域或用户另有要求时按实际组合处理。
- 查询框高度 34px；实际选择值如“全部”使用 `#515a6e`，占位提示仍为 `#ccc`，选择值在内框 32px 行高内垂直居中。
- Select 的 placeholder 与已选值必须由组件状态区分，不能通过对 `.ivu-select-selected-value` 或所有内部 `span` 的全局颜色覆盖把真实值染成提示色。日期范围提示需要非对称间距时，开始文本、分隔符、结束文本和两侧 gap 分别配置；禁止用空格数量、`word-spacing` 或整段 `letter-spacing` 代替单侧间距。
- 表头字重 600；序号列根据内容居中。首列表头文字距表格左边界 18px 与列居中应同时测量，不能只看单元格 padding。操作列每行的操作靠左并保持 16px 间距；多操作列内容区两侧各 18px，整列只有一个操作时沿用右侧 32px。单行操作数量不同不等于整列单操作。
- 有横向溢出且需要操作列时使用官方右固定列；静态导出中表头和内容共用水平滚动区域。宽度足够时取消覆盖层并呈现完整主体列，不能以某张页面的固定断点或固定表宽判断；保持表头与行同步。选择合适列宽以确保操作完整可见。
- 分页器默认第 1 页、每页 10 条、共 100 条演示记录，视明确要求调整；右边缘与表格边缘对齐。验收时在正常和缩放视口检查可见边缘、固定列及纵向滚动，演示总数不能当作真实数据。

# 菜单展开、提示与状态

`sidebar` 的 `open_names` 缺省时只展开 `active_name` 的祖先；明确传入的展开列表（包括空列表）优先。`toolbar_notice(id, text)` 可通过 `table_panel(..., notice=...)` 放到表格工具栏左侧，图标 16px、与灰色文字间距 2px，和右侧按钮垂直居中；未提供提示时不添加内容。按钮在正常和缩放视图检查图标与文字对齐。

状态标签使用 `light_tag` 及官方 Tag；`color='default'` 为浅灰，`color='blue'` 为浅蓝。其他状态按当前业务配置，勿把特定页面状态写死为全局映射。检查生成页面中实际文字、背景、边框颜色和可见性，尤其表格内，避免样式被覆盖后仅凭 DOM 节点存在判定通过。

## 摘要与步骤条

页面确有摘要标题时，标题使用 `summary-title`，20px，标题与相邻标签垂直居中；标题及关闭图标分别距模块对应的上、左或右边界 16px，关闭图标颜色 `#808695`。`summary-header`、`summary-title` 和 `summary-meta` 负责内容布局；模块内边距和关闭图标颜色须在当前 Tree 或适配中显式配置并检查，不能仅靠角色名称推定已实现。

步骤条按当前原型配置步骤数量、名称、状态及时间，不复制旧页面数据。可为官方 Steps 设置 `designRole: progress-steps`：步骤头、数字、标题和连接线应垂直居中，时间与对应标题左对齐，已完成标题为 #515a6e；末项预留约 150px 给时间，其他步骤共享剩余宽度，末项不留整列宽的空白。内容较长或窄屏时依实际内容调整并防止溢出；不得依靠原型中最后一步尚无时间来决定宽度。集中复核正常及缩放视口，临时验证首末步骤都显示时间时不溢出，完成后还原当前原型状态；确认连接线、标题和圆形实际对齐。角色不能代替实际尺寸与视觉检查。

表单字段标签的括号内容确属补充说明、且过长挤压控件时，可将说明移至左侧 Remix `information-line` 提示图标，保留核心字段名称。图标 16px、颜色 `#808695`，与文字间距 2px 且垂直居中；提示内容来自当前原型或明确要求，不推测或丢失核心信息。用户明确要求交互时按相应能力启用并验证；其他静态控件不添加 hover 行为。现有通用角色未提供此标签提示组合，须按当前组件能力配置并验证，不能声称已经自动支持。

# 分区表单与页面操作栏

桌面分区表单默认四列，字段不足时仍保留四列栅格；仅在用户明确要求或具体布局确有需要时显式配置三列。`form_section(..., columns=4)` 为默认，`columns=3` 可选，窄屏按空间调整。

可编辑明细表是录入表，保留当前原型的初始行数，不套普通列表补足十行和分页的默认规则。表格下方的新增按钮可配置 `designRole: detail-add`：无内边距和边框、与表格左边界对齐、距表格底部 16px。操作项用 `detail-action`、官方 Link 和 Remix 图标组成；删除采用 `delete-bin-line`，图标 16px，文字与图标一起垂直居中。操作列 `align: center`，表头和内容共同居中；按具体需求允许其他对齐方式。不要把所有表单表格的链接统一改成删除色。

页面底部有固定操作栏时，滚动到底后最后一个模块背景底边距操作栏顶边 40px；计算时同时考虑末模块的外边距、内容区底部留白和操作栏高度，避免重复叠加。对模块内的实际表头与操作组水平中心、操作组与行垂直中心、按钮相对表格位置和滚动到底部的间距进行浏览器测量并复看；修正后重新检查实际交付页面。

同时单独检查最后内容至模块背景底边的距离；固定操作栏外部的 40px 不代表模块内部留白合理。仅在布局确有需要时使用 `fill:true`，记录理由并检查正常、较小视口下是否产生异常空白。独立模块在主内容区保持平级；容器可用 `layout.paddingX`、`layout.paddingY` 分别配置横纵内边距（使用现有间距 token，优先于对应方向的 `padding`），并实测结果。

`form_section(id, title, fields)` 接收当前任务显式配置的官方 FormItem 节点，区块左右外边距 24px、区块间距 16px。标题无灰底，16px、`#17233d`，蓝色竖线高 16px、间距 6px；标题与内容间距 24px，区块内边距 16px。四列网格按需组合，字段行间距 24px，最后一行不附加行间距；窄屏可换两列。查询网格行间距同为 24px。日期图标使用 Remix `calendar-line`，禁用态沿用官方组件。

表单、上传区、明细表与后续表单在同一区内相邻时，可按任务使用 24px 间距；避免同时叠加标题 margin 与父容器 gap。独立模块由页面主区分别持有，使用实际背景边界计算间距，不用额外业务分组容器替代其平级关系。重复时序列需要等宽时，以最宽实际内容（含状态和操作）确定共同最小宽度；空间不足时横向滚动，并检查表头、正文和右固定操作列的对齐。

`uploaded-value` 默认隐藏删除图标且不启用鼠标效果；可为该节点设置 `previewState: "default" | "hover"` 固定展示状态，或用 `{"bind":"row.preview"}` 按行绑定，值必须为上述两种。只有用户明确要求鼠标经过效果时才设置 `hoverPreview: true`；导出的静态页面只为该节点开放经过效果，输入框仍不可编辑。不要按行号推定状态；复核默认、展示和明确启用的经过状态，检查图标与文字居中及固定列滚动。该角色不实现删除操作。

`page_actions(id, buttons)` 按显式按钮配置生成底部固定操作栏：高 56px、顶部分隔线 1px `#e8eaec`、按钮间距 12px、右内边距 24px；层级低于侧栏并与顶部导航一致，内容底部留空间避免遮挡。没有侧栏时从视口左边缘开始。只在页面确有整页操作时使用，用户明确要求优先。验收检查正常及小窗口下标题、行距、底部遮挡、日期图标和禁用态。
