只读本次页面相关部分；判断直接进入完整Tree、现有来源观察和同一次综合审查，不增加方案文件、截图轮次或审批。

## 页面任务与状态的决策检查

在一次Tree编写中根据本次原型判断，以下是有条件的组合经验，不是所有页面必备模块；用户明确要求和本次原型优先：

1. **识别任务和承载单位。** 普通记录列表采用适合的筛选、工具、表格与分页；登录、汇总工作台、资源监控、时段行情、日历及固定矩阵按各自任务和数据单位组织，不强套列表两块或10条。工作台可包含入口、指标和图表；逐时段交易可使用重复卡片；资源调控可组合资源选择与所选对象监控。布局及数据以本次证据为准。
2. **表达上下文和作用域。** 将全局导航、页内Tabs、分组标题、表单操作、整表工具与行操作按其实际对象放入对应父区域；筛选区Tabs与结果区Tabs分别记录所影响的区域。详情可能包含对象摘要、分组信息及局部明细，不得为套列表而丢失关联上下文。判断刷新作用范围，工具栏与表头保持可见间距；不凭相邻案例补按钮。
3. **记录状态差异。** 当前画面中的选中、展开、禁用、只读、业务状态、开关及不同记录的操作分别绑定；同类页面不同阶段可能改变字段和操作，不只改变颜色。状态信息保留文字语义；截图不能证明切换条件、权限或隐藏状态。涉及导入步骤时，保留原型显示的当前步骤、文件、提示和适用操作，不从错误报告入口推断错误画面。
4. **区分示例数据与真实空态。** 普通列表遵循用户确认的10条示例政策并内部标记演示数据；备注等可选值可部分为空。原型明确的整表或局部空态须保留，局部为空时保留其标题、必要上下文及其他有数据区域；不补造真实数值。固定时段、汇总行、矩阵等按业务结构保留。
5. **检查表单和整体关系。** 普通桌面筛选按标签左、控件右；四列时三项可同排放操作、四项满则操作换行右对齐，适配内容和宽度。查询、重置、可用的收起/展开依约定排序；折叠无依据时不虚构。导航表达层级；Logo与侧栏列宽及顶栏对齐，头像名称成组、末尾工具有内边距，侧栏背景延伸到容器底部。页面与模块标题只在定位、分组或明确要求需要时保留。
6. **图表、表格与数据含义对应。** 按可见证据保留指标、图例、单位、时间和状态、分组表头及汇总关系；不按图形外观猜测精确数据或联动。官方组件和图表能力以实际已核实来源及Adapter为准，无法实现时按既有流程记录缺口。

同一次集中审查对照原型和结果核对上述适用关系，尤其检查菜单语义、表单操作位置、工具栏间距、行差异及局部空态；只对实际测量成功的关系报告自动通过。观察用于指导生成，不自动成为项目规范、iView官方规范或已验证的运行能力。

## 页面骨架与区域

- 普通查询列表常由查询模块和内容模块组成；查询模块可有Tabs，表格状态Tabs也可属于内容模块。由控件控制对象决定归属，不自动添加标题、工具栏、字段或页签。
- 详情、编辑、仪表盘和分析页可以是分组信息、查询与图表、图表加表格、左右主辅区域或多图网格；两块查询列表不是通用强制模板。承载抽屉、对话框、提示及底层页面时保留原型当前可见层次。
- 品牌、侧栏、顶部及主内容遵循实际所属关系。品牌背景与侧栏共享列边界；侧栏背景覆盖整列，不能在菜单末尾断开。视觉对齐、图文与容器边界一起进入骨架，尺寸与颜色使用已核实官方能力。
- 主体内容按重要性和长度分配空间，不把字段、表格列或图数区域机械等分。折叠区域退出内容流时，下方内容随之重排；不将原图某个像素差固化为规则。
- 分类/指标数量导致网格末行留空，可以是有意义的布局；内容容器或表格应合理占用可用空间。先理解关系，不把所有留白视为缺陷，也不复制模块填空。

## Tree 中表达的语义和状态

- 原型图层树可能将不同区域扁平放在同一画板；结合边界、标题、相邻关系和业务作用重建语义层级。图标、头像、徽标、单位、前后缀、箭头、选中和禁用外观与文字作为组合记录。
- 记录每个控件和操作所在区域及其作用对象；页级、表格行级和抽屉内的同名操作均保留。嵌套Tabs、局部筛选、来源切换与页面级筛选不能合并。
- 勾选、关注、开关、在线、业务状态、进度和当前选中是不同维度；不可因为颜色相似互相替代。相同名称在不同列表、不同区域或不同作用域出现，不按文字去重。
- 保留当前静态选中、展开、局部空态、关闭和可见操作，无需实现交互。仅凭灰色不能确定disabled或readonly，仅凭角标/标题无法推断隐藏记录和控制逻辑；矛盾或疑似残留标明证据，不能静默编造或作为默认规则。
- 同类状态可能改变字段、摘要、图表和操作，而不仅是标签颜色；以本次画面为准。不同记录的空值、状态和操作分别保留，避免把示例行复制成完全同一状态。

## 数据列表、表格与分页

- 普通查询列表通常是独立查询区与表格区，工具栏、选择列、说明与导入导出按需要出现。单元格内的多个动作分别理解；组件变体同时考虑形状、填充、图标和用途。
- 先区分普通业务记录、汇总行、分组表头、固定分类矩阵、详情子表和时序采样。汇总只填写适用指标；保留明确空单元格；组内列与单位保持对应。用户指定的10条和分页默认应用于普通列表，具体规则见[列表条数、空值与裁切](PROTOTYPE_OBSERVATION_QA.md#列表条数空值与裁切)。
- 表格分页属于其内容模块的底部而非固定贴视口；普通列表默认第1页、每页10条、共10页及每页条数选择，真实总数未知时100仅为内部标记的展示示意。
- 表头与同列内容按其语义及官方能力对齐，标识、描述、时间、状态和操作列按内容安排；不假设所有数据列必须采用同一种对齐方式。

## 分析页与图表（仅涉及图表时）

- 根据任务表达上下对照、总览加分项、平级网格或图数并列。图和表可能处于同一业务区域；空数据可能只影响其中一个区域。
- 保留每个图的标题、图例、系列角色、单位、时间粒度、坐标轴、正负范围、堆叠/分组、线柱及图表与数据表对应关系。颜色、单位和图例在当前图内绑定，不能跨图默认同一颜色代表同一业务含义。分类矩阵和汇总行不靠普通列表政策复制数据。
- 图表截图只证明视觉与已标注的意义，不能凭图片声称取得完整数据、精确数值、联动或hover行为。原稿图表与数据存在矛盾时保留疑点，不用随机数据宣称真实。
- 以上为设计决策，不意味着当前HTML执行器已经支持图表库、所有复杂表格或浮层。优先核实官方组件、项目依赖与现有Adapter；本地缺通用适配时按既有流程补齐或如实说明能力缺口，不写页面名称分支、不伪称官方提供或已经验证。继续保持静态交付与官方样式约束。

## 放入已有的一次综合审查

复核本次原图与三态结果：区域及控件归属、字段附属信息、状态/动作作用域、数据行差异、图表或多级表头及实际溢出。仅针对本页出现的关系检查；自动检查和视觉判断分别如实记证据，不增加每个经验一轮审核，不以文本数量或组件存在证明语义正确。

## 导航、筛选和表格关系的执行

- 编写Tree时区分全局快捷导航、局部内容Tabs、可展开父菜单与不可展开分组；父子关系、当前项及可见展开状态均明确。组件名称正确仍需检查呈现，横向Menu可能有近似Tabs的下划线，应结合原型及官方能力选择，不以是否使用Tabs作为唯一验收。
- 顶栏将头像和名称放进单独容器，组内与组间距离分别配置；最后工具与右边缘保留容器内边距。品牌区宽度和侧栏共享边界，并核对Logo与顶栏视觉中心；仅在明确需要矩形中心一致时声明`vertical-center`，光学对齐仍需截图检查。
- 常规查询按字段、操作作为一个表单布局：桌面四列中三项可将操作放在同一行最后一列，四项占满时操作另起一行靠右，受实际宽度及特殊控件影响可换行。查询、重置、展开按已约定顺序，折叠功能需有依据。不要把按钮放在与字段分离的标题行。
- 普通列表在导航能说明位置时不额外添加页面标题和“筛选查询”“数据列表”等装饰标题；需要区分内容或提供上下文时保留。刷新作用于列表时可置于表格工具区，不无条件增加或移动与其他业务范围相关的刷新。工具栏和表头之间明确留白，Tree中对适用的相邻区域声明`minimum-gap`，按已核实官方间距token选值，见[关系检查](HTML_FAST_WORKFLOW.md#布局关系检查)。没有实际工具栏时无需创建占位。
- 同一状态切换需保留共同上下文并分别记录筛选、行操作、局部空态及按钮变化；不从静态截图推断未展示的业务联动。查询、图表、时段卡片等按各自作用域组织，不把普通表格默认强加于固定分类或时序数据。
- 在已有综合复核中对照原图和截图逐项判断导航语义、父子层级、头像组、右边距、品牌对齐、查询操作相对字段位置、工具栏与表头间距和标题必要性；只有声明且成功测量的关系才可标记机器检查通过。其他关系必须记录实际视觉证据或未验证，不因整体PASS自动认为通过。\n
