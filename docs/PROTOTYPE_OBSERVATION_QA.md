# 原型观察与内容验收

这份记录用于把截图中的“实际可见”与最终页面的“应当保留”分开。它是当前原型的审核材料，不是固定页面模板，也不提供视觉尺寸。开始布局前完成一次逐区观察；后续各阶段复用同一来源编号，避免反复重新读图。

## 来源观察清单

记录原型文件及其 SHA-256，并按区域为每条可见内容分配稳定编号和位置说明。除了文字、字段、表格列与可见数据，也要记录图标、头像、徽标数字、输入框前后缀、下拉箭头、按钮内图文顺序，以及几个元素是否属于同一个控件。无法辨认具体图标时记录其可见形态和用途为 Review，不猜测图标名称或资产。

每条观察只作一种决定：

| 决定 | 所需记录 | 后续检查 |
| --- | --- | --- |
| 纳入 | Tree 来源项及文字或非文字属性、控件关系 | 骨架标注，默认组件结构，最终可见结果逐项对应 |
| 排除 | 原型中的位置和可核对的理由，例如工具悬浮层或被划除的旧稿 | 最终页面不得悄悄带入；审核中可追溯 |
| Review | 不确定点、可能的两种解释及其对页面的影响 | 影响功能或主要内容时，在骨架前请用户确认；未解决不得把相关内容记为 PASS |

疑似遗留元素不能仅凭“不好看”“不符合 iView 风格”排除。结合区域归属、同类控件的一致性、业务关系及原型工具边界判断；证据不足时保留 Review。保留原始观察，不用归一化 Tree 改写截图事实。排除或 Review 的判断只影响本次原型，不继承到下一张图。

## 四次核对共用一份清单

1. **Tree**：每条来源观察都有决定；纳入项的文字、非文字属性和控件关系均映射到 Tree，排除项有理由，Review 对应的问题已解决或阻断相关区域。只校对文字不足以通过。
2. **骨架**：纳入项对应区域和组件选型；图标槽位、头像、徽标、下拉等附属结构须有可见标注。检查整页关系与官方布局依据。
3. **默认组件**：通过官方组件 DOM 与截图验证控件类型和附属结构，尤其检查 Input 的前后缀、Badge、Avatar、Dropdown 等。文案暂用默认内容，不因未填原型文字而漏掉结构。
4. **交付**：以来源观察清单逐项对照原型和整页截图，核对文字、数据、图标、头像、徽标、控件类型及图文相对位置；对排除项复核理由。记录未覆盖、不可见或不一致项并返回最早受影响阶段修复。

QA 保存原型哈希、每条观察编号及决定、Tree 绑定、各阶段截图哈希和逐项结果。自动检查可核实已记录项的结构与 DOM，但不能证明 AI 没漏看截图里的元素；必须有人或模型独立查看原型与最终整页截图，明确记录非文字元素的校对结论。不可把仅检查文字、组件数量或页面可渲染的结果写成完整 PASS。
