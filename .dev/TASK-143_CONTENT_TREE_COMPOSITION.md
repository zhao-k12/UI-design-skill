# TASK-143 内容 Tree 驱动官方组件组合

## ARCHITECTURE_CONFLICT 与用户决定

旧入口按页面选择Profile；既有树表和职务页编译器分别固定列数、菜单、行操作和页面区域。把本地适配缺口当成官方缺组件，使普通页面变化反复进入开发。

用户明确要求灵活组合、不能写死页面结构，并批准“让生成器按内容Tree配置菜单、工具栏、表格列和行操作，而不是每换一种页面开发一套”。据此新增通用声明式Tree编译和递归HTML翻译入口；保留理解→Tree→布局→映射→UI-IR→Adapter边界。无需再次征求相同架构决定。

HTML调用锁定包的官方组件，无需按页面或尺寸重新准入；官方导出及源码哈希作为运行包来源登记。历史Figma/Penpot组件保真条件仍属历史链路。仅官方确实不提供能力时才称为组件缺口；本地不能翻译某个属性/插槽属于通用适配缺口，应补组件级通用映射，不新增业务页面分支。

## 验收范围

本任务验证同一执行器以不同配置生成不同区域次序、平级/分组菜单、不同工具栏、列数、状态/操作单元格和行数。配置测试是开发样例，不是用户新原型或旧页面重新验收。保留四类结论的一次综合复核与静态导出；不添加审核关卡。

## 已实施与结果

- `html_composition.py`递归编译container/component/text/icon/repeat及命名插槽；按使用的官方导出登记组件，锁定包源码、输入、编译器和UI-IR字节。布局只允许关系与官方间距Token，组件style/class/event覆盖被拒绝。
- `composition.mjs`递归调用官方组件，Table列单元格子Tree翻译成官方render接口，行操作通过绑定和repeat组合。不存在页面名称、列数、行数或动作名称分支；默认态与交付态沿用同一结构。
- `export_html_composition.mjs`在同一浏览器会话保存三态截图、动态结构指标和静态快照，内嵌官方CSS/字体/图标，记录执行字节和QA边界；运行PASS不代替原图综合视觉复核。
- Skill入口、执行说明、组合契约、约束补充和README入口同步。历史页面脚本保留复现用途，不再作为新任务路由。
- Skill格式检查PASS；4项Core测试PASS：未预先按页面准入的官方Alert可解析、官方不存在的组件明确报错、来源覆盖缺失拒绝、组件外观覆盖拒绝。
- 1项浏览器端到端测试覆盖两份不同配置，PASS：3/5列表格、2/1行、平级/分组菜单及对应箭头、区域重排、4/1个绑定图标操作、状态Tag变体、默认文案分离和静态无脚本输出。开发证据位于`artifacts/task-143/composition-smoke-*`。没有重写或重新宣称TASK-142页面验收。

这是对声明式组合和所测组件路径的验证，不表示所有官方组件的每个高级API均已实测。首次遇到实际未支持的属性或插槽时按组件级补通用翻译，不退回业务页面生成器。
