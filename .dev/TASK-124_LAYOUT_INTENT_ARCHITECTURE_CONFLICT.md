# TASK-124 — 原型画法被误用为页面布局

## 当前设计与冲突

V0.3 的统一内容 Tree 由已完成的 Core 运行反推；同一 Core 运行的布局计划在 TASK-122 中从旧示例复制。布局器只按已给尺寸与 Token 计算，不判断计划是否符合页面规范。组件放置只要求固定来源组件装进 Cell，不要求填满应填的容器。骨架 QA 与最终截图 QA 检查执行是否符合计划，没有检查计划的设计质量。因此，1392 px Table 放入 1872 px 列表区域，以及页头／列表内容相对各自表面 0 px 留白，均被放行。

## 用户批准的方向

用户要求 skill 理解原型内容、主动补充规范化页面结构，并按设计规范调整，而非复刻原型位置。保留五步主流程；在语义 Page Tree 已审核、Core 布局运行前，由模型建立来源明确的页面设计意图。原型仅约束内容、顺序和明确的业务关系；视觉几何由锁定设计规范、项目页面规则和组件能力决定。模型可补容器、留白、对齐与占宽，不得发明业务数据。程序继续负责 24 栅格与几何执行，Adapter 不做设计决策。

本次以独立 V0.3.2 布局质量门落地，先覆盖 `list-page` 的页头／查询／列表内边距、列表表格占宽及组件宽度能力；这是项目页面规则，不能表述为 iView 对所有页面的官方固定数值。旧 Registry、字节锁、任务页面不原位修改。其它页面模式没有项目规则时进入 Review，不能把当前规则泛化。

## 完成边界

新布局门必须对 TASK-122 冻结输入给出 FAIL，能指出零内边距与表格宽度缺口；对满足同一规则的独立布局样本给出 PASS；新原生阶段缺少该门 PASS 必须阻断。此任务不迁移 Table Registry，不重画 Figma 页面，也不声称已有页面通过新门。
