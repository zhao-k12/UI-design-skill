# TASK-145 常见页面5分钟目标与紧凑入口

用户批准减少重复记录、临时辅助脚本、碎片工具调用及截图后窄列返工，并以收到原型至交付5分钟为常见页面目标。此为对当前HTML路线的已批准执行优化，不新增审核阶段，不放弃Core/UI-IR、官方组件、原图复扫或最终视觉校对。

## 调整

- 常规任务只写job.json及实际看图后的review.json。新增统一`html_fast_workflow.py`的start/render/finalize：分组观察、独立复扫、Tree来源绑定、关系及视觉复核由共享展开器产生逐实例证据。重复数据仍逐条保留在Tree，例外按id记录，数量/traits不匹配继续被拒绝。
- start记录任务开始，render完成Core及单会话三态截图，返回REVIEW_REQUIRED；finalize核对当前runId、source、页面和截图哈希，执行既有综合门后才发布任务根目录page.html。分组展开不能自动生成视觉PASS，旧复核和篡改截图不能沿用。
- 原有递归Adapter增加由Core声明的官方内容适配预检：实际字体、单元格padding、文字、Avatar和Button自然宽度计算Table最小列空间，经官方width/minWidth生效，截图前解决常见挤压。列可fitContent:false保留特定宽度；不覆盖官方CSS，不按原型像素定义样式。分组表头等未覆盖路径仍须视觉判断。
- timing.json保存起始、各次prepare/Core/render及复核等待/总耗时；漏start则范围明确为render-start，targetMet为null。目标300秒非硬截止，不因超时交付FAIL或省略审核。
- Skill、执行说明和原型观察说明统一到快速入口；深层契约、官方新能力与历史资料按需读取。既有分步入口保留调试恢复用途。

## 验证边界

开发样例不等于用户新原型。紧凑记录的展开、例外、重复id、来源组绑定与不自动确认视觉PASS有定向测试；端到端覆盖两条记录配置的render→实际开发测试检查→finalize、计时、40px窄列预检扩展、无脚本快照和旧run复核拒绝。原有两结构配置浏览器回归继续验证不同菜单、列数和行操作。

尚未用完整新用户原型从收到图片开始测得5分钟结果，不能宣称目标已达成。此次交付的是减少重复工作、提前排版检查及准确计时的机制。

实际结果：8项紧凑输入定向测试与5项既有组合Core测试PASS；两结构旧组合浏览器回归PASS；快速入口端到端测试PASS，包含旧run和截图变动拒绝。Skill格式及diff检查PASS。初次端到端测试暴露空关系列表兼容问题，已在展开器补齐明确的空列表后重测通过；没有删除既有审核条件。原型中确实重复的数据可用`$repeat`加明确例外表达，执行器仍保存逐条展开的数据与来源编号。
