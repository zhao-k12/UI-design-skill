# TASK-052 — Penpot 写入完成与布局等待超时混淆

日期：2026-10-14。

当前设计：`adapters/penpot/runtime.js` 在全部原生节点创建完毕后调用 `penpot.waitForLayoutUpdate()`；此等待器抛出超时会被通用 `native_write_failed` 捕获，返回 `nativeExecution=PARTIAL`。独立的结构与视觉 QA 原本应在写入状态之后执行。

实际原因：TASK-052 的 1920×1080 完整页面创建了 93 个原生节点，末尾等待器超时；随后独立读回确认 93 个节点、24 段文字、四个组件与两个图标实例，根画板与三个区块尺寸正确，原生 PNG 导出完整。超时不是写入动作失败，现有状态将已完成写入误报为部分执行，并阻断独立 QA。重跑同一计划会制造重复页面。

影响：Penpot 原生执行状态和阶段恢复语义不准确；完整页面无法进入正式 QA。Figma、Core、UI-IR、Registry 均不受影响。

限定处理：仅在 Penpot 基础 Adapter 中移除写入函数末尾的布局等待，让 `EXECUTED` 只表示所有同步/异步原生写入已完成。布局稳定、节点身份、尺寸、字体、组件链接和视觉导出继续由独立只读捕获及 QA 判定；验收未通过仍不能发布。对原超时页面保留证据，不自动重复写入。
