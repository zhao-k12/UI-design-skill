# TASK-050 — 双平台默认字体测量与单一布局输入

日期：2026-10-14。状态：RESOLVED（用户批准双端较大值）。

当前设计：V0.1 的 `runtime-measurements.json` 只锁定一份 Figma 来源捕获，`layout-plan.json` 的文字尺寸和组合单元尺寸均据此验收。V0.2 则允许 Figma Inter 与 Penpot Source Sans Pro 各自的默认字体，同时 Core 仍须平台无关。

冲突原因：同一文案的原生文字宽度可能跨平台不同。直接沿用 V0.1 测量会把旧字体证据冒充为新版本；仅改 Figma 数值又不能证明 Penpot 不溢出。现有 Runner 的 `sourceCapture` 为单文件引用，不能分别辨认两端原始捕获。

影响：在两端自由文字、组合单元的完整原生读回和来源哈希锁定前，不能宣布 V0.2 输入锁或完整页面流水线 PASS。

决策：用户明确选择按 `uiIrId` 的 `max(width)` / `max(height)` 生成平台无关的保守包络。分别保存两端原生捕获和 SHA-256，包络逐项保留两端尺寸与节点 ID。组合单元仍遵循已批准几何和组件真实尺寸，不能把自由文字自然宽度当作整个单元宽度。V0.1 文件保持原状。文字包络已实现并验证；组合单元与完整输入仍待验收。
